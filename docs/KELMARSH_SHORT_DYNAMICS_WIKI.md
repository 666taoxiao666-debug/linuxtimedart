# Kelmarsh：短时动态案例检索

日期：2026-10-15。用户授权继续修正模型、测试、推送、服务器训练。

## 诊断与本轮修改

上一轮v8正式输出MAE101.853466、RMSE155.602775、R²0.782868；共同底座为
101.888844/155.471020。只改善MAE而RMSE恶化，不是联合精度提升；置信区间跨零。

首先检查“案例陈旧”：原案例最后目标2016-09-15，后续685个early训练窗口到10月2日。
只用训练标签将这些案例加入旧读出，内部selection MAE/RMSE从118.395880/184.749656
变为115.124158/178.924554，但稍晚训练calibration从185.841766/250.270708
恶化到197.545982/258.863315。因此不采用“直接加入新案例就更好”的方案，不增加案例标签。

实际预测1–2小时，旧Wiki键主要是12小时均值、两个6小时半段的差值、最后功率/桨距/朝向；
没有最后风速、转速及1/3小时功率/风速/转速差。数值网络虽然保存了72小时输入，
不等于Wiki检索读到了这些短时变化。训练memory段未来功率增量与最近3小时功率差的相关系数
为-0.4459/-0.3175，旧6v6差为-0.1096/-0.1531；early段最后风速为-0.0948/-0.2263。
这些只是训练关联，不保证外层收益，也不主张可获得未来风况。

本轮只给Wiki距离坐标补8个固定短时量，使用完全相同fit scaler，沿用原32邻居、0.95支持分位数、
事件/运行状态、同一360窗口案例来源、相同readout和相同1361参数置信网络。只在同一案例上
重新估计距离标准化和支持半径。原案例的标签、风机、时间、成熟时刻保持逐项一致；
数值输入、功率标签、scaler、切分、底座、loss/LR/20epoch预算、效用门槛均不改。

## 冻结实验

协议：`configs/kelmarsh_short_dynamics_protocol_v9.json`。
入口：`scripts/train/Kelmarsh_launch_short_dynamics_wiki.sh`，默认动态共享资源限制。
仅fold1 seed2024，一次新的20epoch置信网络。复用v7/v8所有已完成对照，不重复训练。
按原115窗口训练侧段选epoch，随后110窗口绑定新实际专家的收益证书；外层只报告。
新案例ID、距离实现、scaler/base、数值门ID、检查点、实际校准输出全部进入身份链。
另外固定confidence=1的直接案例读出作为诊断，不搜索阈值。

主要验收是正式DynamicsWikiSelective的MAE和RMSE同时优于共同数值/Persistence、
旧键CaseAnchoredWikiSelective、FreeWikiSelective、ZeroMemorySelective、DirectDynamicsCaseSelective。
raw结果全部保留，不允许看到外层后提升为主方法。只跑一折开发证据，不自动扩seed/fold。
报告MAE/MSE/RMSE/R²、双Skill、容量容差命中率、逐步长指标、介入/伤害/不介入、
时间块bootstrap和Newey–West配对统计与预测图。

## 【最终评级】：C（运行前）

现有结果仍不支持Wiki的稳定额外精度贡献；本轮是针对遗漏短期状态的可证伪修正，未检索新颖性，
不承诺创新评分或精度提升。外层已被历史开发查看，不能当独立确认集。

## 【必须立即修复Top 5】

1. 短预测步长与检索坐标的时间尺度不匹配：本轮补1/3小时观测动态。
2. 不把“更近案例”直接等同于更可信：训练侧较晚段已否定该简单策略，本轮不采用。
3. 坐标更新必须更新实际执行身份和收益证书，不复用旧证书。
4. 对照产物按真实v7/v8来源加载，不能假定复用结果已复制到新目录。
5. 评价必须是双误差改进并保留全部负结果，不能用raw或单折显著性替代主要检验。

## 【需重跑的实验与需补充的单元测试】

只运行新增v9单折；不重跑v7/v8。新增测试覆盖固定lag索引、仅改Wiki视图、同案例标签/风机/时间
不变、查询标签独立、运行状态/成熟时刻、源码/底座身份、持出风机排除和真实对照路径。
沿用案例方向/幅度限制、实际训练与断点复用、收益证书和共享GPU控制测试。

## === 详细问题清单 ===

- **严重级别**：P2（模型归纳偏置，不是已证明的数值bug）。
  **位置**：`utils/kelmarsh_hourly_wiki.py -> keys`与`data_provider/kelmarsh_hourly.py -> physical_context`。
  **触发条件及证据**：h2预测主要使用12小时摘要，缺少最近1/3小时动态；上述训练关联非零。
  **影响**：相近摘要可能对应不同临近状态，错误近邻可传递错误案例方向。
  **修复**：新增`utils/kelmarsh_short_dynamics_wiki.py`，只追加8个因果短时量。
  **验证**：固定lag坐标测试；同案例/标签预算；同参数网络与旧键配对。
  **置信度**：对遗漏高；对它是主要精度瓶颈中等，需真实实验。

- **严重级别**：P2（证据复用风险，已防护）。
  **位置**：新runner `prepare/run`及新距离模块`validate/candidates`。
  **触发条件及证据**：坐标、近邻或网络变化后实际修正对象已不同，旧收益不能直接迁移。
  **影响**：复用旧证书会将其他专家收益归给新执行器。
  **修复**：源目录逐文件哈希检查、新pack/案例/源码ID、新检查点和实际校准输出证书绑定。
  **验证**：篡改案例或底座拒绝、未来时间拒绝、held-out标签拒绝；完成后实际输出复算。
  **置信度**：高。

- **严重级别**：P1（结论边界）。
  **位置**：协议`primary_success/limitations`与最终报告。
  **触发条件及证据**：已有多轮查看同一开发外层；v8双误差未改善。
  **影响**：不能将继续试验当独立确认，也不能靠调整阈值宣称Wiki有效。
  **修复**：一次预声明修改，双误差验收；不达标保留负结果，不调阈值或seed。
  **验证**：新run的protocol、结果与对照预测/统计逐项核验。
  **置信度**：高。
