# 本项目GPU资源策略（2026-10-15用户最新授权）

目标：只有我方训练时不人为限速；检测到其他GPU计算任务时，才对我方实施共享约束。
这是执行资源策略，不改变模型参数、标签、batch size、loss、LR、seed或实验轮数。

实现：`utils/gpu_runtime_policy.py`。v7启动器
`scripts/train/Kelmarsh_launch_certified_fallback.sh`和v8启动器
`scripts/train/Kelmarsh_launch_case_anchored_wiki.sh`默认开启自适应，`--shared`保留为显式别名，
`--idle-only`仍可选择完全等待空闲的保守模式。未集成该工具的历史启动器不被悄悄更改。

- `solo_unrestricted`：没有其他GPU计算PID时，将本进程PyTorch allocator fraction恢复为1.0，
  不做20ms批次等待；PyTorch/可用BLAS线程上限恢复到当前CPU affinity可用核数。
  这不是预分配全部显存或保证GPU利用率100%；小模型按需占用，不制造无用计算。
- `shared_limited`：有其他GPU计算PID时，保持约2GiB的本进程PyTorch allocator上限、
  2个数值计算线程、批次后同步并等待20ms；开始/切入共享需要至少6GiB空闲，持续检查
  至少4GiB空闲。此cap不包括全部CUDA驱动开销，延迟也不是10%算力硬配额。
- 运行中每约1秒在检查/训练步安全点查询全部计算PID，排除自己，不靠一次0%利用率判空闲。
  有人退出就自动解除限制，有人加入则尝试切换。查询失败不当成空闲。
- 切入共享前只释放本进程未占用的缓存；已有活跃张量/保留内存仍超预算，或空闲量不足，
  则停止我方任务，不通过调整别人任务来“腾显存”。普通非共享模式检测到新任务也会退出。
- 不调整CPU nice值，避免降低优先级后普通用户无法恢复的非对称问题；仅动态调自身线程数。
  不启用MPS/MIG，不改整卡功耗、时钟、计算模式，不向任何其他训练进程发信号。
- `resource_policy.json`记录当前模式、全部切换事件及其看到的其他PID。检测不是实时隔离，
  不能保证完全不减速或绝不OOM。调度/线程变化也不能承诺跨机器逐bit完全一致。

本地52项相关测试通过（其中11项资源策略测试），含独占→共享、共享→独占、缓存/活跃内存
边界、失效查询、身份排除与单进程自停。服务器部署后同样运行测试；本次不为测试策略重训
已经完成的v7，旧结果与其当时的固定共享资源记录保持原样。
