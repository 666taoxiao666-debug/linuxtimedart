## 阶段名

v35 P3：Penmanshiel 多年滚动确认。2022、2023 两年做确认，2024 只描述；一次冻结、一次运行。

背景：
- P2 的开发证据在 `output/penmanshiel_hourly/p2_v35/`：Penmanshiel 2021，3 个 seed。R、F1、F3 获得支持；Z1、Z2 本次开发实验未获得支持。按预登记，R 满足进入 P3 的条件。
- 用户 2026-11-03 提出把多次实验合并一次跑完：每往后一折，训练多加一年、验证用下一年。这里采用"滚动折"。
- 三折在同一个实例里冻结、训练、评估，所以不可能根据前一年的结果去调后一年。

## 目标

1. 在从未打开过的 2022 年、2023 年上，分别确认 R：上游 MIDAS 特征在第二个风场、另一组站网上带来增益。这是论文主贡献的外部证据，两年都确认才算最强。
2. 在同样两年上确认 F1、F3：只有 1 个月或 3 个月本场数据时，Kelmarsh 迁移配方优于从零配方。
3. 2024（只有部分风机）和 Z1、Z2 只描述，不作确认主张。

## 假设与判定标准

- **每折的评估**：该折测试年的 ALL 队列，h1–4 合并，单位 kW。3 个 seed 先平均损失，再做统计（与 P2、v32 相同）：
  - MAE 用起报时间聚类的 Newey–West 检验；
  - RMSE 用起报时间块自助法，块长 8，5000 次。
- **确认族**：每个确认折内只有 R、F1、F3 三个比较，Holm 校正只在折内这三个之间做。
  - 确认条件（同 P2，事先设定）：MAE 增益 CI95 下界 > 0，且 Holm p ≤ 0.05，且 RMSE 增益 CI95 下界 > 0。
- **窗口门槛**（事先设定）：测试年的 ALL 窗口数必须 ≥ 5000，该折才能做确认；不足就自动降为只描述。
  - 2023 年部分风机缺 1 月，预计能过门槛（待确认）。
- **R 的总体表述**（事先设定）：
  - T22、T23 都确认 → "两个独立年份确认"；
  - 只有一年确认 → "部分确认"，写明是哪一年；
  - 两年都没确认 → "未获确认"。
  - 三种情况都要报告效应大小、CI 和 p 值。F1、F3 按同样方式表述。
- **只描述的内容**：
  - T24 折的全部结果；
  - 每折的 Z1、Z2；
  - FT-3 与 P-upstream 的差距；
  - normal 队列、分 h1–4 的增益、R²；
  - 每年的风机覆盖和 upstream_missing 占比。
- **表述规则**：
  - F1、F3 只比较两套完整配方。FT-1 如果选回 epoch 0，就写成"直接使用 Kelmarsh 模型优于从零训练"。
  - 结果出来后不改阈值、不换比较、不补跑。

## 执行顺序（一个实例内，每步失败就停）

1. **冻结协议**：Codex 把本节写成 `configs/penmanshiel_p3_protocol_v35.json`（三折、臂、确认族、阈值、门槛、表述规则），runner 里用 `PROTOCOL_SHA256` 锁住。单独提交并推送之后，才能解封。
2. **解封核对**：
   - Penmanshiel 2022–2024 年的归档和 11 个站 2022–2024 年的文件，SHA256 要与 D2-0 的登记一致（`test_year_registration.json`、`input_hashes.json`）。
   - 用 P1 同一套准备代码重建 2016-08–2024 的数据。2016–2021 的每一行、每个标签都要与 P1 产物完全相同；这一步不通过就停。
   - 报告每年的风机覆盖和窗口数，并据此确定 T23、T24 是否过门槛。
3. **训练**：完成 72 次拟合，全部选定并冻结，写入 `selection_freeze.json`。
4. **只评估一次**：之后才在 2022–2024 上计算指标。
- **补跑规则**：只有第 4 步之前的技术失败，才允许修复后补跑，最多 2 个实例。任何测试年的指标一旦算出，不补跑、不改。

## 风险（≤5 条）

1. 某一年的天气与开发年差别大，可能只有一年确认。表述规则已经事先写好，照规则写。
2. R 的增益集中在 h2–4，P2 里 h1 为 −1.0 kW；h1 再变差属于正常。
3. 2023、2024 年覆盖不全，较晚年份的站点缺测也可能更多。门槛和描述都事先定好，不事后调整。
4. 这三年用完以后，Penmanshiel 就没有未用过的年份了。解封或准备出任何问题都应停下交用户，而不是带着问题评估。
5. 72 次拟合比 P2 多 3 倍，运行中断的风险更高。runner 要能断点续跑，已冻结的拟合不重训。
