## === 详细问题清单 ===

### 1. 最终执行的“原底座”在fold1是零残差回退

- **严重级别**：[P1]，针对训练贡献/比较叙述，不是认定早停实现有错。
- **位置**：`models/TimeDART.py` -> `Model.__init__`，456–476行将预测头置零；
  `forecast`，1331–1338行输出最后观测功率加有界残差；
  `scripts/train_kelmarsh_hourly.py` -> `train_stage`，235–238及268–270行保留内部最佳epoch。
- **触发条件及证据**：f1_s2024实际完成5轮，但最终 `best_epoch=0`。
  `head.forecast_head.weight`、bias的最大绝对值均为0，门控logit为−2.2。
  OriginalTrend与Persistence预测最大仅差0.0000532242 kW，来自数值反变换精度。
  f1_s2025、f1_s2026也选epoch0；f0/f2六组选择了非零epoch，不能扩展成“全部底座没训练”。
- **对论文结论的影响**：本fold的预训练/骨干/提示模块并未通过最终预测头表现为
  相对Persistence的学习增益。OriginalTrend与Persistence不能重复计作两次独立强基线胜出。
- **修复方案**：先修正结果命名与归因，保留回退结果。另立训练侧协议研究骨干是否
  能同时改善目标指标，不能因为外层看过结果而改选epoch1。内部epoch1 RMSE从
  181.076484降至178.967376，但MAE从115.596765恶化到117.390452；当前MAE选模回退合法。
- **验证修复的测试**：零头→最后功率身份测试；manifest/所选epoch/checkpoint/预测一致。
- **置信度**：高，已读保存的CPU检查点与训练曲线；没有GPU推理或重训。

### 2. 数值残差的内部收益在后续时间段翻负

- **严重级别**：[P1]，针对泛化与部署有效性；失败不等于标签错位。
- **位置**：`scripts/train_kelmarsh_contextual_expert.py` -> `tensor_data`，76–79行；
  `train_arm`，116–153行；`infer`，83–89行；`data_provider/kelmarsh_hourly.py`，97–117行。
- **触发条件及证据**：同一NumericContext选epoch9，20轮完整训练；训练标签只来自风机1—5。
  按时间顺序，MAE相对原底座的收益为：memory拟合段+15.245504 kW、early拟合段
  +13.076991、内部选择段+6.220628、后续训练校准段+1.892955，外层开发段−5.348070。
  前两段为拟合内效果，不能当独立验证。阶段风况/功率分布不同；此序列支持收益衰减的
  观察，不单独证明某个物理变化是唯一原因。
- **对论文结论的影响**：选模段同时改善MAE/RMSE，不能保证未来收益。仅看一段内选
  或跨风机平均的正收益比例不构成任意时间漂移下的保证。
- **补充量化**：内部选择目标平均功率435.23 kW，后续校准524.64，外层全体309.20；
  外层仅风机1—5时平均321.20，MAE依然从103.539833恶化到108.992492（−5.452659 kW）。
  因此不能只归咎风机6。外层第一、二步分别恶化4.070426和6.625713 kW；
  六台风机只有风机4改善，风机1/2/3/5/6恶化。
- **误差分解**：平均修正−18.530483 kW，使bias从−1.567901变为−20.098384。
  但MSE增量2403.733624 kW²中，bias平方只占401.486738（16.70%），
  误差方差项增加2002.246886（83.30%）。简单加一个常数偏置并不能解释全部问题，
  更不能用外层标签拟合这个常数。
- **修复方案**：另行批准后，将残差适配器本身视为可拒绝的执行候选；用训练期多个
  前向时间块检验收益与兼容性，保留零修正动作。不通过时回退，不能只靠更多epoch。
  这是一项待验证方案，不承诺改善。
- **验证修复的测试**：分块边界、执行器身份、拒绝后精确回退；最终独立冻结评估。
- **置信度**：高于“泛化失败”观察；中等于具体漂移机制，缺少独立因果对照。

### 3. 已有数值校准不是当前冻结Wiki回退路径

- **严重级别**：[P2]。冻结对照的实验控制是正确的；将它当最终默认输出则需要额外证据。
- **位置**：`scripts/train_kelmarsh_contextual_expert.py` -> `numeric_calibration_mask`，173–184行；
  `run`，303–307及325–331行；`scripts/train_kelmarsh_wiki_quality.py`，136–149行；
  `scripts/train_kelmarsh_incremental_wiki.py`，282–294行复用该NoWikiUnchanged缓存。
- **触发条件及证据**：保存的 `numeric_calibration.json` 为 `[false,true]`。
  训练校准第1步虽然平均MAE收益+0.741843 kW，但仅3/5风机受益（60%），未达2/3；
  第2步4/5受益而通过。NumericCalibrated因此首步回退、第二步保留数值适配器。
  外层MAE/RMSE为105.201701/159.014057，优于未校准107.236914/163.018317，
  但仍差于Persistence的101.888844/155.471020。
- **对论文结论的影响**：仅比未校准适配器微弱改善，不足以证明优于已有非Wiki方案。
  新Wiki的107.206703/162.994570也差于该现成校准对照。
- **修复方案**：报告完整对照；不能事后把NumericCalibrated换入v6冒充Wiki改进。
  如新协议采用更安全数值回退，所有Wiki/记忆置零分支须共同使用同一冻结新回退。
  单纯接上现成两步门仍不够，因为第二步的训练正收益也已在外层翻负。
- **验证修复的测试**：lead0被拒绝时逐点等于原底座；所有分支共享回退数组哈希。
- **置信度**：高，代码、训练校准记录和已完成外层结果一致。

### 4. MIXED 0.2的名称掩盖了误差单位不同

- **严重级别**：[P2]比较口径；[NEEDS-EVIDENCE]作为主要退化原因。
- **位置**：`scripts/train_kelmarsh_hourly.py`，255–257行使用全局标准化功率误差；
  `scripts/train_kelmarsh_contextual_expert.py`，78及139–140行使用除额定容量的残差误差。
- **触发条件及证据**：该fold功率Scaler尺度为461.917962 kW，适配器除数为2050 kW。
  对物理误差e，损失为 `0.8*abs(e)/s + 0.2*e²/s²`。
  消去整体比例后，相同e下的二次项相对一次项权重在原底座中约为适配器的4.438倍。
- **对论文结论的影响**：不能声称只是换结构、损失完全相同；但不同尺度本身不是
  计算错误，也未证明改统一尺度就会改善外层。
- **修复方案**：预先明确优化目标及共同训练期固定尺度；如做实验，应单独控制此变量，
  不同时改LR、架构、Wiki门槛和seed。本轮不实施。
- **验证修复的测试**：相同kW误差向量在预声明共同尺度下得到相同损失/相对权重。
- **置信度**：高于尺度不等价事实；低于它对当前负收益的因果份额。

### 5. Wiki支持范围与主要退化位置并不一致

- **严重级别**：[P2]，作用边界，不是证书索引错误。
- **位置**：`models/IncrementalWindWiki.py` -> `forward`，63–64行；
  `scripts/train_kelmarsh_incremental_wiki.py` -> `evaluate`，294–300行。
- **触发条件及证据**：本组原始Wiki增量实际产生非零修正的270/1276个预测点之外，
  还有1006点（78.8401%）保持冻结数值输出。在这些非介入点，数值MAE相对原底座
  恶化4.231020 kW，贡献整体MAE退化3.335741 kW，占总退化5.348070的62.37%。
  这是本次实际干预掩码的分解，不是所有可能知识规则的理论上界。
- **对论文结论的影响**：不能期望只处理少量Wiki案例，就直接消除未触及区域的数值退化。
  并不意味着介入区域永远不可能补偿整体误差，更不许可删掉非介入评估样本。
- **修复方案**：保持全样本评估，分别报告数值退化与Wiki净贡献。是否修改数值回退
  需用户另行允许，不能偷偷扩大Wiki覆盖或用外层伤害率调门槛。
- **验证修复的测试**：非支持步严格零增量；干预/非干预误差贡献之和等于全体差值。
- **置信度**：高，已由保存的预测和实际干预数组复算。

## 现在可以说什么，不能说什么

同协议固定配置下，本组DLinear MAE113.384676、PatchTST118.663658、Ridge158.395838，
都没有超过Persistence。这说明当前实现/信息集/训练协议没有把学习模型的优势跑出来，
不能据此证明这些模型类别普遍无效或Kelmarsh数据损坏，也不能用“超过两个神经基线”
掩盖负的Persistence Skill。各项完整RMSE/R²见诊断JSON和结果面板。

目前优先级应是：确认底座执行身份 → 研究残差收益的训练期时间稳定性与可拒绝性 →
冻结新的非Wiki回退 → 才重新隔离验证Wiki贡献。具体修正机制仍待训练侧证据和新协议验证。
这比继续刷同一个外层验证集的Wiki阈值、epoch或seed更有根据。

诊断阶段曾因非Wiki范围限制未实施。2026-10-15用户明确授权直接判断、修改及服务器训练，
该障碍已解除；不需要再次询问同类实施步骤。原始标签、旧检查点与旧结果仍保持不变。

## 2026-10-15 实施更新：v7可拒绝数值残差

- 新协议：`configs/kelmarsh_certified_fallback_protocol_v7.json`，单fold1/seed2024。
- 不再默认执行整个NumericContext残差。旧训练selection仅拟合每步长的[0,1]凸收缩系数；
  在后续训练证据的三个固定连续时间块上检查MAE/MSE、风机支持和受益比例；任一块失败则回退。
- 原fresh calibration按不同issue时钟分为三段，跨边界目标移除：数值执行证据、Wiki选epoch、
  Wiki新执行器证书。三者与outer目标隔离，证据时间必须在实际预测issue时已可用。
- 新Wiki与同参数记忆置零分支都用同一个已冻结数值执行策略，各20epoch；不重训旧底座。
  每个新证书绑定实际增量检查点、数值门ID、原数值/底座检查点、质量bank和训练数据哈希。
- 数值回退修正不能归为Wiki创新或Wiki精度贡献。必须同时报告Persistence、OriginalTrend、
  旧原始数值、旧NumericCalibrated、旧v6 Wiki及新共同底座与匹配消融。
- v7重新分配了内部选epoch/校准样本，v6-v7仅为系统对比，不能孤立地归因于某一知识组件。
- 时块检查只是一条经验风险控制规则，不是统计覆盖保证或新时段必正收益的证明。
  outer历史已被开发查看，不能将新结果称作独立确认。
- 本地新增10项测试连同31项相关回归共41项通过，Bash语法通过。部署与实际运行状态以
  `docs/KELMARSH_CERTIFIED_FALLBACK_V7.md`的记录为准；本报告不预先声称精度改善。

本地与服务器审查源代码一致。TimeDART的原始文件哈希差异来自CRLF/LF换行；
统一LF后的SHA256一致，不能把换行差异误判成执行模型不同。
